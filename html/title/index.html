The <title> Element

As defined in the HTML Living Standard, the <title> element represents the title of the document. It is a required element and must be a child of the <head>.

Example: 
<head>
  <title>Accessible Web Design Guide</title>
</head>

The title is not rendered within the body of the page, but it is critical for browser tabs, bookmarks, and search engine results.

The Accessibility Powerhouse

For users of assistive technology, the <title> is the most important piece of metadata on the page.

WCAG Requirement: Page Titled

Success Criterion 2.4.2 (Level A): Web pages have titles that describe topic or purpose.

When a screen reader user navigates to a new page, the <title> is the first thing announced. Without a descriptive title, the user has no immediate way of knowing if they have landed on the correct page or what the page contains.

Understand SC 2.4.2: Page Titled

Best Practices for Accessible Titles

  • Be Specific: Instead of "Home", use "Home | SimpleAccess.io".
  • Front-Load Key Info: Put the unique page topic first, then the site name (e.g., "Table Tag Guide | SimpleAccess.io"). This allows screen reader users to distinguish between multiple open tabs quickly.
  • Avoid Redundancy: Do not repeat the same title across every page of your site.

A11y Tip: Dynamic Titles

For Single Page Applications (SPAs), use JavaScript to update the document.title whenever the view changes. This ensures that the browser's history and screen readers reflect the current state of the application.
